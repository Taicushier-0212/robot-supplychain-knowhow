# 最小闭环（SOP · 状态机 · RACI · 授权 · 异常 · 复盘）

先跑通一条能关门的链，再加表单和工具。本页是总图；细则链到现有文档，不另起一套平行流程。

## 一句话

```text
定规格（G0）→ 锁图纸申购（G1）→ 询价/首件（G2）→ 下单跟单（G3）
  → 来料判定（G4）→ 异常有单（NCR）→ 关单回写（G5）→ 坑写进 knowhow
```

没有「微信私了」的出口。三条铁律见 [原则](./principles.md)。

## 最小闭环（v1 必做）

人少也可以兼岗，下面 **检查项不兼丢**：

1. **G0 写清**：买什么、几套、哪些必须打样；长周期标红。  
2. **G1 有 PR**：图纸/料号版本锁死，审核人写进单。  
3. **G2 该打样的打样**：FAI 未 Pass/Conditional 不进量产 PO。  
4. **G3 只认 PO**：含税、交期、账期、收货地址齐全；变更书面。  
5. **G4 先检后发**：待检隔离；Pass 或已会签 Conditional 才能发料。  
6. **异常开 NCR**：Fail 必开；让步必书面、限批次；安全/高压/承力禁止口头让步。  
7. **G5 回写**：数量、质量、交期进台账；有 NCR 的 PO 没有复盘结论不算关完。  
8. **可复用结论进仓库**：口径进 knowhow / docs，合同电话不进本仓。

卡在哪一道，就停在哪一道——不要用「先装上再补单」绕门。

## 授权矩阵（初期）

金额档、电子签以后再加。先冻 **决策权**：

| 决策 | 谁拍板（A） | 谁执行（R） | 红线 |
|---|---|---|---|
| SKU / 可买范围 / 规格冻结 | 产品（结构/电气/关节按域） | 计划 + 供应链 | 未冻不下正式单 |
| PR 审核通过 | 使用方域负责人（机加→结构，板→电气…） | 供应链 | 无版本不询价 |
| 选定供应商（非独家） | 供应链 | 采购 | P0 ≥2 家书面报价 |
| 独家件立项 | 产品 + 供应链共管 | 采购标红 + 备份计划 | 原因必须写进卡点 |
| 下 PO / 书面变更 | 供应链 | 采购 | 口头加单无效 |
| IQC 判定 Pass/Fail | —（判定权在 IQC） | IQC | 仓储不改结论 |
| Conditional 让步发料 | 使用方域负责人 | 供应链组织会签 | 安全/高压/承力禁止 |
| NCR 关闭 | 供应链（SQE 缺岗时负责人） | SQE / 采购 | 无证据不关 |
| 供应商降权 / 暂停新单 | 供应链负责人 | SQE | 重复 L2/L3 必评估 |
| 规格让步永久改图 | 原冻结方（结构/电气/关节） | 计划升版 | 升版 = 旧报价作废 |

空缺代签规则仍以 [RACI](./raci.md) 为准，姓名写进该 PR/PO。

## 异常分级（L1 / L2 / L3）

与 IQC 的 Pass / Conditional / Fail **同时用**：等级说严重度，判定说能不能发料。

| 级 | 含义 | 典型 | 动作 |
|---|---|---|---|
| **L1** | 不影响安全与接口，可限批使用或挑修 | 外观、轻微毛刺、短装可补 | 可 Conditional；记录；可不升级供应商会 |
| **L2** | 功能/接口/尺寸不过，本批不能当合格品 | 错版、开短路、关键尺寸超差 | Fail + NCR；隔离；退换/返工；关单前要有结论 |
| **L3** | 安全、高压电气、承力、危货合规 | 裂纹承力件、绝缘不足、电芯无认证混放 | 立即隔离；禁止口头让步；负责人知情；评估是否停该厂新单 |

现场先由 IQC 给判定 + 建议等级 → 供应链按级走 NCR/会签 → 僵持升级见 [RACI 争议升级](./raci.md)。

## 闭环复盘（怎么才算关上）

```text
异常发生
  → 隔离实物 + 开 NCR（写清级、PO、料号、缺陷）
    → 处置：返工 / 退换 / 让步（限批）/ 报废
      → 证据：供应商纠正、影响批次、是否改检规
        → G5：交期与质量回写评分；重复 NCR → 降权
          → 可复用口径：用卡片模板写进对应 knowhow 页
```

**G5 未完成信号：** 账不平、NCR 仍打开、同一坑第二次出现却没有 knowhow 结论。

复盘写结论，不写私人联系方式。模板：[knowhow-card](../templates/knowhow-card.md)。

## 明确不做（v1）

- 不上复杂风控模型、不先上 ERP 再谈流程。  
- 不建第二套「项目管理 Gate」和 G0–G5 抢戏——项目里程碑可以另表，买料仍走本门。  
- 授权不按「谁官大」临时改；要改就改本页和 RACI，并通知在途单。

## 迭代顺序（有余力再加）

1. PO 金额授权档（例如超 X 需产品共签）——数字放作业仓库，本仓只留规则句式。  
2. 供应商记分卡（交期/质量/配合）与季度复盘。  
3. NCR 时效（打开→处置→关闭的天数）。  
4. 电子流与待办，状态机字段与 [gates](./gates.md) 对齐即可。
