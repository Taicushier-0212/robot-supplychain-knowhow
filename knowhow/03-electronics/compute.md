# 算力 / 主控

**大类：** [电子器件](./README.md)

跑规划、视觉、全身调度的计算单元：工控机、边缘 AI 模组、核心板 + 载板、自研主板。不负责关节电流环——那是 [驱动器](../01-joint-modules/driver.md)。

只看「多少 TOPS」不够下单。接口、供电、散热、镜像和总线主站能力没冻，到货就是一台能开机的砖。

## 在机器人里干什么

| 它管 | 它不管 |
|---|---|
| 轨迹与步态规划、全身协调 | 关节电流环、换向 |
| 视觉 / 力觉感知融合、推理 | 减速器、编码本身 |
| 总线主站（EtherCAT / CAN 等）发周期指令 | PACK 成组与 BMS 保护细节 |
| 日志、遥控、上位调试通道 | 母线预充与大电流配电 |

和驱动的咬合看 **总线周期、同步方式、掉线行为**，不要只对「有没有这个口」。相机带宽、算力峰值和供电峰值会叠在一起，见 [电源模块](./power.md)、[线束](./harness.md)。

## 先分清买的是什么

| 形态 | 是什么 | 选型时盯住 |
|---|---|---|
| **整机工控 / 盒子** | 带壳、电源、常用口已引出 | 抗振、安装、风扇策略、长期供货 |
| **核心板 / SOM** | CPU 周边焊死，口在载板上 | 核心板型号 + 载板谁做；针座寿命与供货 |
| **开发板 / SBC** | 树莓派式整板 | 样机可以，量产要问工规、锁料、散热 |
| **自研主板** | 芯片级贴片 | BSP、散热、EMC、最小起订与改版周期 |

口头「一块 RK3588」可能是芯片、核心板或整机。PO 上写清 **形态 + 具体型号 + 内存 / 存储配置**。

## 选型轴（所有主控通用）

### 算力与软件

- [ ] CPU 架构与核数；是否需要实时核 / 协处理器
- [ ] NPU / GPU 算力及 **框架支持**（ONNX、TensorRT、RKNN、OpenCL…）
- [ ] 内存容量与带宽；是否可焊死不可换
- [ ] 存储：eMMC / SSD；镜像分区与 OTA 方式
- [ ] 目标系统：Linux 发行版、内核版本、是否要 PREEMPT_RT

TOPS 是峰值宣传值。视觉链路要冻：分辨率 × 路数 × 帧率 × 模型，在目标板上跑通再锁料。

### 接口与总线

- [ ] 运动总线：EtherCAT 主站 / CAN / CAN-FD / RS485——**主站是板载还是外插网卡 / 扩展**
- [ ] 相机：MIPI CSI 路数与线长限制；USB3；千兆 / 2.5G / 10G 网口
- [ ] 调试与外设：HDMI / DP、USB、UART、GPIO、I²C、SPI
- [ ] PCIe 通道：能不能插独立网卡、采集卡、SSD

人形里最常见的坑：算力够，**没有靠谱的 EtherCAT 主站**；或主站有了，和相机抢 PCIe / 带宽。

### 供电、热、结构

- [ ] 输入电压范围、峰值电流、上电时序
- [ ] 额定功耗与峰值功耗；降频温度点
- [ ] 散热：外壳导热、热管、风扇是否允许；倒装 / 封闭躯干余量
- [ ] 体积、安装孔、抗振；线束出线方向

桌面风扇测通，不代表塞进胸腔还能满频。温升按整机姿态和最坏工况验。

### 供货与变更

- [ ] 芯片 / 模组停产策略；第二货源是否允许
- [ ] BSP 与驱动谁维护；内核升级谁回归
- [ ] 样品、小批、量产是否同一硬件版本（内存颗粒换代要重新验）

## RK3588

瑞芯微 **RK3588** 是人形 / 边缘视觉里很常见的一档：8 核 CPU（4×A76 + 4×A55）、Mali-G610 GPU、片内 NPU（厂家口径约 **6 TOPS**）、多媒体和 MIPI 接口多。相对高端 NVIDIA 模组更便宜、货源渠道多；相对纯 MCU / 弱 SBC，更适合多路相机 + 轻量推理 + 上层调度。

### 它适合干什么

- 全身调度、导航与中等复杂度视觉（检测、分割、姿态）的主脑或副脑
- 多路 MIPI / USB 相机接入后的采集与预处理
- 样机到小批：核心板 + 自定义载板，先把接口铺齐再冻结构

### 它通常不单独解决什么

- **硬实时电流环**：仍在关节驱动器上
- **高可靠工业 EtherCAT 主站**：很多消费级 3588 板只有普通千兆口，主站要 **专用网卡 / 扩展方案 + 验证过的协议栈**，下单时单独冻，不要默认「有网口就能主站」
- **大模型端侧满血推理**：6 TOPS 是 NPU 峰值口径；大参数模型、高分辨率多路同时跑，要实测帧率与占空，不能按宣传 TOPS 反推

### 选型时必须写清的 3588 字段

| 字段 | 为什么 |
|---|---|
| **RK3588 还是 RK3588S 等衍生** | 接口裁剪、封装、功耗与供货不同，不能混称「3588」 |
| **核心板品牌与型号** | 同样 3588，DDR、PMIC、PCB 层数、散热焊盘差很多 |
| **LPDDR 容量与颗粒** | 8G / 16G 等；换颗粒可能动时序，小批要备案 |
| **eMMC / SSD** | 容量、是否可更换；刷机口与线序 |
| **MIPI CSI / DSI 路数与排线** | 相机几路、线长、转接板谁做 |
| **网口数量与芯片** | 几路千兆；是否预留 PCIe 给 EtherCAT 主站卡 |
| **USB3 / Type-C / HDMI** | 调试、显示器、外设是否冲突复用 |
| **供电** | 典型 5V / 12V 输入方案；峰值电流与座子 |
| **BSP** | Linux 版本、内核、设备树；RKNN / 相机 ISP 驱动是否在冻结镜像里 |

### 和 Orin / x86 工控怎么比（口头口径）

| | **RK3588 模组** | **NVIDIA Jetson 类** | **x86 工控** |
|---|---|---|---|
| 成本与货源 | 相对低，渠道多 | 高，生态完整 | 中高，工业口成熟 |
| 视觉 / CUDA 生态 | RKNN / 开源栈，迁移有成本 | TensorRT 成熟 | 通用，但 NPU 弱或靠独显 |
| 运动总线 | 常要外加主站方案 | 同样常要验证主站 | 可选配卡多 |
| 热设计 | 封闭机身要认真做 | 功耗档位更高，热更紧 | 看盒子与风扇 |

不是「3588 一定不如 Orin」，而是：**软件栈、主站、热和供货**哪条是你的硬约束，就按那条选。

### RK3588 常见坑

- 买开发板当量产：插座、DDR 焊接、供电保护都不是工规口径。
- 默认板载网口做 EtherCAT 主站，联调阶段才发现抖动或不支持。
- 只锁「RK3588 + 16G」，不锁核心板型号，小批换厂后设备树全改。
- NPU 6 TOPS 写进方案书，多路 4K 相机一开就 CPU / 带宽先满。
- 散热按官方散热器裸板测，装进金属胸腔无导热垫，降频表现为「规划莫名变慢」。
- Android 演示镜像和 Linux 控制系统不是同一条 BSP，验收系统要写死。

## 冻结清单（下单用）

- [ ] 形态：工控 / SOM+载板 / SBC / 自研；完整型号
- [ ] SoC（如 RK3588 / 3588S）、内存、存储
- [ ] 目标 OS 与镜像版本；刷机与恢复方式
- [ ] 运动总线主站方案（板载 / 扩展卡 / 外置）及周期
- [ ] 相机接口与路数；是否需要独立 ISP / 转接板
- [ ] 供电电压、峰值电流、连接器；与 [电源](./power.md) 对齐
- [ ] 散热方案与允许环境温度；是否允许风扇
- [ ] 安装尺寸、抗振；线束与 [接插件](./connectors/README.md) 出线
- [ ] 供货周期、第二来源策略；是否禁止到货换核心板

## 验收要点

- 冷启动、掉电重启、看门狗
- 外设枚举：网口、USB、相机、总线主站
- 持续满载（CPU + NPU + 相机）温升与是否降频
- 总线周期抖动（有主站时）
- 镜像版本与核心板丝印 / 批次一致

## 已知坑

- 只看 TOPS，接口不够当主站或相机不够路。
- 散热按桌面测，装进封闭躯干过热降频。
- 样品核心板与小批不同厂，设备树和 NPU 驱动对不上。
- 主控与驱动器共地、共电源设计不清，总线一接就复位。
- 相机和电机动力线绑在一起，视觉误码当「算力不够」。
